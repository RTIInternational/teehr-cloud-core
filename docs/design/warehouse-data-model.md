# Target warehouse data model (v0 draft)

- **Status:** Draft v0 — Phase 0 design artifact, input to ratification and spikes
- **Date:** 2026-11-10
- **Related:** #133, [phased plan](https://claude.ai/artifact/NDYWNmX5biKrBvPuZAdsNE), ADR-0001 (layout), ADR-0005 (units), ADR-0002 (metric engine)

This is the greenfield, canonical schema the platform is built against. Existing data is
**ported** into it once (validated backfill), not carried forward. It is a draft to react to, not
a settled schema.

## Principles

- **Greenfield, canonical.** Redesign clean; do not inherit the compound `variable_name`, string
  units, or denormalized vocabularies.
- **Star, not full 3NF.** Normalize the *vocabularies* into small validated reference tables, but
  keep the *fact* tables wide for scan performance.
- **Table-per-dataset within a project namespace** (ADR-0001). A dataset has a type and lives in
  its own Iceberg table; a project is a Polaris namespace.
- **Write gateway enforces the schema.** No writer bypasses it (ADR-0004).
- **Canonical units + provenance** (ADR-0005). Store canonical; keep the original value and unit.

## Namespaces and datasets

- `core` namespace holds the public TEEHR data and the **shared reference vocabularies**.
- Each project is its own namespace; its datasets may reference `core` vocabularies and data.
- A **dataset** is one typed Iceberg table. Dataset types:

| Type | Holds | Notes |
| --- | --- | --- |
| `timeseries` | observed / simulated / forecast values | the primary fact table |
| `locations` | points or polygons + attributes | geospatial, arbitrary attribute columns inline |
| `crosswalks` | id ↔ id mappings | e.g. gage ↔ model feature |
| `attributes` | location attributes (optional) | only when not carried inline on `locations` |

Derived datasets (regenerated, not migrated — ADR-0006): `joined_timeseries`, `metrics`,
summary/completeness tables.

## Reference vocabularies (controlled, in `core`)

Small validated tables; every fact-table code column is a foreign key into one of these.

- **`variable`** — the measured quantity only (e.g. `streamflow`, `precipitation`,
  `air_temperature`). No interval or statistic baked in.
- **`interval`** — the time step / accumulation window (e.g. `instantaneous`, `hourly`, `daily`,
  `PT1H`, `P1D`).
- **`statistic`** — how the value is reduced over the interval (e.g. `instantaneous`, `mean`,
  `sum`, `max`, `min`).
- **`unit`** — canonical unit plus its dimension signature (for the registry, ADR-0005).
- **`configuration`** — the data source / model configuration (e.g. `usgs_observations`,
  `nwm30_retrospective`, `nwm30_short_range`), with its kind (observed / simulated / forecast).

### The compound-name split

The legacy `variable_name` (e.g. `streamflow_hourly_inst`) becomes **three columns**:
`variable` + `interval` + `statistic`. This is the single most load-bearing schema change — it
makes grouping, unit semantics, and cross-dataset joins well-defined instead of string-parsed.

## Fact table — `timeseries`

Wide table, one row per observation/forecast value. Columns (v0):

| Column | Type | Notes |
| --- | --- | --- |
| `location_id` | string | FK to a `locations` dataset; stable id (e.g. `usgs-14181500`) |
| `configuration` | string | FK to `configuration` |
| `variable` | string | FK to `variable` |
| `interval` | string | FK to `interval` |
| `statistic` | string | FK to `statistic` |
| `value_time` | timestamp | the time the value is for |
| `reference_time` | timestamp, nullable | forecast issue time; null for observed/retrospective |
| `member` | string, nullable | ensemble member; null if deterministic |
| `value` | double | **canonical** unit |
| `unit` | string | FK to `unit` (canonical) |
| `original_value` | double, nullable | provenance |
| `original_unit` | string, nullable | provenance (FK to `unit`) |

Partitioning / sort: by `configuration`, `variable`, and time — to be confirmed by the storage
spike against real query shapes.

## Fact table — `locations`

- `location_id` (string, stable), `name`, `geometry` (`GEOMETRY`), plus **arbitrary attribute
  columns** inline (drainage area, stream order, …) rather than a separate attributes table
  (ADR-0001). Id conventions carried forward where they encode meaning (e.g. `usgs-` points vs
  `usgsbasin-` polygons).

## Fact table — `crosswalks`

- `primary_location_id` ↔ `secondary_location_id` (+ optional `weight` for many-to-one
  aggregation). Used to pair observed and predicted series across id spaces.

## Derived — `joined_timeseries`, `metrics`, per-chunk state

- **`joined_timeseries`** — observed paired with predicted on `location_id` (via crosswalk) and
  aligned time, plus derived fields. Regenerated by the spec run, not hand-maintained.
- **Per-chunk state** — per `(group, unit-of-time=month)` sufficient statistics (counts, sums,
  squared sums, cross-products) for moment-based metrics, and mergeable sketches (histogram /
  t-digest) for order-statistic metrics (ADR-0002). Serves both incremental recompute and block
  bootstrap. Run outputs must **not** be only final metric values, or this is blocked.
- **`metrics`** — group-by key columns + `metric` name + `value` + `unit` (metric-aware,
  ADR-0005) + bootstrap CI columns (`ci_lower`, `ci_upper`, `ci_level`, `seed`). The group-by
  columns are the table's uniqueness key.

## Lineage (every derived row / run)

`run_id`, `spec_version`, `engine_version`, and the **input table snapshot** (Iceberg snapshot id)
of each source — so any result is reproducible.
