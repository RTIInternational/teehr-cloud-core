# TEEHR framework diagrams

Schematic diagrams for the TEEHR-Cloud journal article. The diagrams are generated by Python into one editable draw.io file with one page (tab) per diagram.

## Files

| File | Purpose |
|---|---|
| `teehr-framework.drawio` | The diagrams, one per page. Open it in the draw.io desktop app, at [app.diagrams.net](https://app.diagrams.net), or with the VS Code *Draw.io Integration* extension. |
| `build_diagrams.py` | One function per page, plus the `PAGES` list that sets which pages are built and in what order. |
| `drawio_helpers.py` | Reusable pieces: shared styles and colors, the `Page` class, and `write_drawio()`. |

## Pages

1. **Overall architecture.** TEEHR-Cloud on Kubernetes, top to bottom:
   - Ingress, then Keycloak for identity and access, with Prometheus/Grafana monitoring alongside.
   - Applications: Prefect workflows, JupyterHub, the REST/Download API, dashboards and the gridded data and vector tile API (xpublish).
   - Compute: Spark and Trino.
   - Data warehouse: the Polaris Iceberg REST catalog, plus S3 object storage holding the Iceberg tables, the Zarr/Icechunk gridded data and the PMTiles vector tiles.
   - Two data paths from the shared TEEHR-Python environment of Prefect workflows and JupyterHub. Iceberg tables go through Spark and the Polaris catalog. Gridded data and vector tiles go straight to object storage, bypassing Polaris; this needs storage permissions. The workflows build the PMTiles vector tiles from the locations table.
   - Around the cluster: external data sources, the TEEHR-Python package, external clients, and the infrastructure (AWS via Terraform or OpenTofu, or local kind).
2. **Core and client deployments.** teehr (pip-installed from a pinned git SHA) and teehr-cloud-core (included as a git submodule) feed the teehr-hub and teehr-fved client deployments. Garden deploys each client to a local kind cluster or to a remote AWS EKS cluster, which infrastructure-as-code provisions.
3. **End-to-end data flow.** External data → ingest → core tables → join and add calculated fields → joined timeseries → metrics → metrics and summary tables → API and dashboards. Prefect orchestrates the steps, and JupyterHub gives interactive access to the warehouse tables.
4. **TEEHR-Python overview.** The `Evaluation` components:
   - `fetch`, `load` and `generate`
   - Tables and views
   - Query, calculated fields, `metrics` and I/O
   - The engine layer: Spark, the Iceberg catalog (local or remote) and storage
5. **Local warehouse directory.** An annotated directory tree of a local evaluation.

The data model schematic already exists at `teehr/docs/drawio/data_model.drawio`. Copy that page into this file in draw.io if you want all the figures in one place.

## Running the script

The script needs only the Python 3 standard library.

```bash
cd teehr-cloud-core/docs/diagrams/drawio
python3 build_diagrams.py
```

This rewrites `teehr-framework.drawio` with every page in `PAGES`.

> **Rebuilding overwrites the .drawio file**, including any edits made by hand in draw.io. Either keep the script as the source of truth, or switch to editing in draw.io once a layout is final (see below).

## Editing existing diagrams

There are two ways to edit a diagram. Pick one per diagram so edits don't get lost.

**In the script.** Best while the layout is still changing.

- Change the text, position or size in the page's function in `build_diagrams.py`, then rebuild.
- Every shape takes absolute coordinates: `p.box(id, label, style, x, y, width, height)`. The origin is the top-left corner, and the units are pixels.
- Arrows connect shapes by id: `p.edge(id, source_id, target_id, label, style, points)`. `points` is an optional list of `(x, y)` waypoints that force the route. To pin where an arrow leaves or enters a shape, add `exitX/exitY/entryX/entryY` to its style. These run from 0 to 1 across the shape, for example `"exitX=1;exitY=0.5;"` for the middle of the right edge.

**In draw.io.** Best for the final polish: fine alignment, fonts, and exporting figures.

- Every shape and arrow is a normal draw.io object, and arrows stay attached when you move shapes.
- To protect manual edits from a rebuild, copy the file to a new name (for example `teehr-framework-final.drawio`) and edit the copy. Alternatively, remove that page from `PAGES`. A rebuild still writes a new file, though, so keep your edited copy under a different name either way.
- To export a figure for the article, use *File → Export as → PNG/SVG/PDF*, and pick the page under *Export → Page*. Use a high resolution (300 DPI) or a vector format (SVG or PDF) for the journal.

## Creating a new diagram

1. Add a function to `build_diagrams.py` that builds and returns a `Page`:

   ```python
   def my_new_diagram():
       p = Page("My new diagram", 1200, 800)        # page name, width, height
       p.group("grp-a", "Group label", 20, 40, 500, 300)  # dashed outline
       p.box("a", tb("Title", "Body text"), CORE, 50, 80, 200, 80)
       p.box("b", tb("Other box"), CLIENT, 300, 80, 200, 80)
       p.edge("e-a-b", "a", "b", "label")
       p.legend(560, 40)                             # optional
       return p
   ```

2. Add the function to `PAGES` at the position where the page should appear.
3. Run `python3 build_diagrams.py` and open the .drawio file to check the layout.

**Helpers and styles** (from `drawio_helpers.py`):

- **Styles:** `CORE`, `CLIENT`, `PY`, `INFRA`, `EXT` (colored rounded boxes), `STORE` (a cylinder for data stores), `NOTE` and `TEXT` (plain text), `DASHED` (add to an edge style for a dashed arrow) and `DIRECT` (add to an edge style to draw jump arcs where it crosses other arrows; add that edge after the ones it crosses).
- **`tb(title, body)`:** a label with a bold title and smaller body text. Use `<br>` for line breaks.
- **`p.group(..., sub=True)`:** a lighter dashed outline for nested groups.
- **`p.legend(x, y, items, width, lines)`:** a legend. `items` is a list of `(style, text)` pairs and defaults to the full color legend. `lines` adds arrow samples as `(edge style, text)` pairs.
- **`p.line(id, x1, y1, x2, y2, style)`:** an arrow that isn't attached to any shape.
- **Draw.io styles:** any style string works, so you can copy one from draw.io via *Edit Style* on a shape. In Python strings, escape special characters the usual way; the helpers handle the XML escaping.
- **Ids:** shape and edge ids only need to be unique within a page. Readable ids such as `spark` or `e-api-trino` make the file easier to edit later.
