## Adding docs

- Put a plan in `plans/` when it crosses services or repos, or needs review before work starts. Small, single-PR work can live in the issue or PR description instead.
- Start each plan with a status line, for example `Status: Draft | Accepted | In progress | Done | Superseded by <link>`, plus a date and an owner.
- Don't delete finished plans. Mark them Done or Superseded, and write any lasting outcomes into `reference/`.
- See [`diagrams/drawio/README.md`](diagrams/drawio/README.md) for building and editing diagrams.
